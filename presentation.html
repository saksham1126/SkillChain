SkillChain

Blockchain-Based Skill Passport & Decentralized Credential Verification

A zero-trust academic verification platform leveraging Ethereum smart contracts and cryptographic SHA-256 hashing to eliminate certificate fraud once and for all.

Author: Saksham Pathak
Domain: Blockchain & Web3 Technologies
Tech: Solidity, Hardhat, Ethers.js, React
Context & Motivation

Background & Motivation

The Credential Crisis
  • Degrees, diplomas, and certifications are foundational for employment and higher education.
  • Traditional paper documents and digital PDFs are easily altered using standard image editors.
  • Over 30% of job resumes contain altered or fabricated academic qualifications.
  • Credential fraud is a multi-billion dollar worldwide challenge.
Centralized Flaws
  • Verification requires contacting registrar offices or proprietary third-party portals.
  • Centralized university databases represent single points of failure vulnerable to attacks.
  • Manual background checks take 5 to 20 business days to complete.
  • High administrative and financial overhead for organizations.
The Web3 Opportunity
  • Blockchain provides an immutable, decentralized ledger immune to unilateral tampering.
  • Smart contracts enforce deterministic verification rules without human intervention.
  • Anyone can verify credentials in milliseconds with zero accounts or subscriptions.
  • Cryptographic hashing protects personal data privacy on-chain.
Challenges

Problem Statement: Current Verification Deficiencies

1. Ease of Digital Alteration
Digital PDF certificates and scanned documents can be modified in minutes using graphic software. Changing a student's name, degree class, or issuing date leaves zero detectable trace.
2. Verification Latency & Overhead
Recruiters and institutions must submit verification requests to universities, creating weeks of delay during critical hiring and admissions cycles with high manual labor costs.
3. Database Vulnerability & Tampering
Centralized education repositories are vulnerable to ransomware attacks, unauthorized insider manipulation, and server outages. If the server is down, verification halts.
4. The Revocation Dilemma
When a certificate is cancelled due to academic misconduct, downloaded copies remain in circulation with no real-time mechanism for third-party verifiers to detect revocation.
Solution Overview

Proposed Solution: SkillChain

The Core Vision
"Your Skills. Your Proof."

SkillChain is a decentralized skill passport where certifying bodies anchor cryptographic proofs (SHA-256 digests) into Ethereum smart contracts.

Sensitive student records remain off-chain for privacy, while the blockchain guarantees zero-trust immutability and instant public verification.

Cryptographic Fingerprinting (SHA-256)
Generates a unique 256-bit hash. Even changing a single character alters the hash completely, exposing forgery immediately.
Immutable On-Chain Ledger
Certificate ID, hash, issuer wallet, and timestamp are committed to Ethereum blocks—immune to retroactive tampering.
Instant Public Verification
Anyone can query the smart contract in milliseconds using the Certificate ID without requiring privileged portal logins.
System Design

System Architecture & End-to-End Workflow

01
Certificate Creation
Issuer inputs student name, skill title, issuing organization, and issue date in the React frontend.
02
SHA-256 Digest
Frontend normalizes data, generates unique ID (SKC-2026-XXXX), and computes SHA-256 hash using Ethers.js.
03
Smart Contract
Transaction is broadcast to SkillChain.sol. The contract records ID, hash, issuer address, and block timestamp.
04
Public Verify
Verifier enters the ID. Contract compares computed hash with on-chain hash and flags VERIFIED or INVALID.

Smart Contract Architecture (SkillChain.sol)

Data Structures & Storage
struct Certificate {
    string certificateId;
    string certificateHash;  // SHA-256
    address issuer;          // Signer
    uint256 issueTimestamp;  // Block time
    bool isRevoked;
    bool exists;
}

mapping(string => Certificate) certificates;
event CertificateRegistered(id, hash, issuer);
event CertificateRevoked(id, issuer, time);
Core Functions
  • registerCertificate(id, hash)
    Enforces non-empty params, rejects duplicate IDs, logs issuer & timestamp.
  • verifyCertificate(id, hash)
    Performs keccak256 hash comparison. Returns (isValid, isRevoked, exists).
  • revokeCertificate(id)
    Enforces require(cert.issuer == msg.sender). Sets isRevoked = true.
  • getCertificate(id)
    Public view returning full metadata, timestamp, and status.

Security Architecture

Security, Privacy & Cryptographic Integrity

SHA-256 Data Privacy (Off-Chain Storage)
Sensitive personal details (student identity, grades) are hashed prior to blockchain registration. No private student data is stored in public contract state, ensuring compliance with privacy standards while retaining 100% mathematical verifiability.
Blockchain Immutability & Anti-Tampering
Once a transaction is confirmed in a block, the certificate record cannot be edited, overwritten, backdated, or deleted by any administrative party or attacker. This guarantees zero-trust tamper resistance.
Smart Contract Access Control & Duplicate Prevention
Revocation functions enforce require(cert.issuer == msg.sender), ensuring only the genuine certifying wallet can invalidate credentials. Duplicate registration is eliminated by checking require(!certificates[id].exists).

Demonstration

Demonstration Walkthrough

Step 1: Issue Certificate
Navigate to 'Add Certificate', input student details, and click register. Transaction is mined in Hardhat, returning a unique Certificate ID and real Ethereum Tx hash.
Step 2: View in Passport
Navigate to 'My Certificates'. The issued certificate appears instantly with its issuer, issue date, and an on-chain status verification badge.
Step 3: Public Verification
Enter the Certificate ID on the public 'Verify' page. The application calculates the SHA-256 hash and compares it on-chain to display a bold VERIFIED badge.
Step 4: Negative & Revoke Test
Altering even a single character in the certificate details immediately triggers an INVALID alert. Clicking Revoke updates on-chain state to REVOKED.
